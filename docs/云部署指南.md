# 云部署指南（可选加分 +15）

> 目标：让评审老师能通过**公网链接**打开通讯录。localhost / 127.0.0.1 / 内网地址均不算云部署。
> 本项目前后端共用一个 Node 进程和一个端口，部署比常规前后端分离项目简单很多。

## 平台要求澄清（先看这一节）

原帖 1.4 原文：

> *Deploy the address book on a cloud server, **such as** Huawei Cloud or Alibaba Cloud. A `localhost` link does **not** count as cloud deployment.*

- **不指定云服务商**。华为云、阿里云只是 `such as`（例如）举的两个例子，全文没有任何"必须使用阿里云 / 指定平台"的字样；腾讯云 CVM、任意有公网 IP 的 VPS 同样符合。
- **是可选加分项，不是必做项**。章节标题即 `Web Deployment (optional, 15 points)`，评分标准最后一句也写明 `The optional cloud deployment in Section 1.4 is worth 15 additional points`。不做云部署不影响基础 100 分。
- **唯一的硬约束**：必须公网可访问，`localhost` / `127.0.0.1` / 内网 IP 都不算。
- 开头 checklist 里的 "Deployment" 小节写的是 `Release a version and initiate a pull request` 和写博客，指的是**版本发布与 PR**，与云服务器无关，别混淆。
- 若课程群 / 助教另有口头要求（例如必须自建 ECS 并交服务器配置截图），那属于原帖之外的补充要求，以老师通知为准；本文的 ECS 步骤同样适用。

> 本项目已在云端发布过一个公网可访问的 HTTP 服务链接（见 `docs/博客模板.md` 第 1 节）。它满足"公网访问、非 localhost"，但不是学生自己配置的 ECS 实例；若想更稳妥地拿满 15 分，建议按本文再补一套 ECS 部署，并在博客里写明服务器配置、公网 IP 与安全组。

## 0. 部署前检查

- [ ] 一台有**公网 IP** 的云服务器（华为云 ECS / 阿里云 ECS / 腾讯云 CVM 均可），建议 Ubuntu 22.04 / 24.04，1 核 2G 起步即可
- [ ] 安全组放行 `22`（SSH）、`80`（HTTP）、以及计划使用的应用端口（默认 `3000`）
- [ ] 本地 `npm test` 全部通过
- [ ] 确认 `data/contacts.json` 里没有真实隐私信息（演示数据即可）

## 1. 安装 Node.js

以 Ubuntu 为例（用 nvm，避免系统自带旧版本）：

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
source ~/.bashrc
nvm install 22
node -v && npm -v
```

如果服务器访问 GitHub 慢，可用系统包管理器：`sudo apt update && sudo apt install -y nodejs npm` （需确认版本 >= 18）。

## 2. 上传代码

方式 A（推荐，便于和 GitHub 作业仓库保持一致）：

```bash
sudo apt install -y git
git clone https://github.com/<你的团队>/<仓库名>.git
cd <仓库名>
```

方式 B（本地打包上传）：

```bash
# 在本地执行（排除依赖）
tar czf address-book.tar.gz --exclude=node_modules address-book
scp address-book.tar.gz root@<公网IP>:/opt/
# 在服务器执行
cd /opt && tar xzf address-book.tar.gz && cd address-book
```

## 3. 安装依赖并启动

```bash
npm install --omit=dev --registry=https://registry.npmmirror.com
PORT=3000 HOST=0.0.0.0 npm start
```

打开 `http://<公网IP>:3000` 验证。注意 **`HOST=0.0.0.0`** 必须设置，否则只监听本机回环地址，外网访问不到。

## 4. 用 PM2 守护进程

直接 `npm start` 会在关闭 SSH 后退出，用 PM2 常驻：

```bash
sudo npm install -g pm2
PORT=3000 HOST=0.0.0.0 pm2 start server/index.js --name address-book
pm2 save
pm2 startup        # 按输出提示执行它给出的那条命令，实现开机自启
pm2 logs address-book
```

常用命令：`pm2 status`、`pm2 restart address-book`、`pm2 stop address-book`。

## 5. （推荐）Nginx 反向代理到 80 端口

这样博客里可以填一个干净的 `http://<公网IP>` 或域名，不需要带 `:3000`。

```bash
sudo apt install -y nginx
sudo tee /etc/nginx/sites-available/address-book > /dev/null <<'EOF'
server {
    listen 80;
    server_name _;

    client_max_body_size 10m;   # 允许上传 Excel

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 60s;
    }
}
EOF
sudo ln -sf /etc/nginx/sites-available/address-book /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

防火墙（如启用）：

```bash
sudo ufw allow 22 && sudo ufw allow 80 && sudo ufw allow 3000 && sudo ufw enable
```

> 华为云 / 阿里云还需要在**控制台的安全组**里额外放行 80 和 3000，只改系统防火墙不够。

有域名时可以再申请免费证书：`sudo apt install -y certbot python3-certbot-nginx && sudo certbot --nginx -d your.domain.com`。

## 6. 部署后验证清单

| # | 检查项 | 期望结果 |
| --- | --- | --- |
| 1 | 浏览器打开 `http://<公网IP>/` | 正常显示通讯录首页，样式与图标完整 |
| 2 | 打开 `http://<公网IP>/api/health` | 返回 `{"code":0,...}` |
| 3 | 点击星标收藏 | 侧栏「我的收藏」计数 +1，刷新后仍保留 |

| 6 | 导出当前筛选结果 | 浏览器下载 `.xlsx`，打开后一人一行、列名正确 |

## 7. 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 公网打不开，本机 `curl localhost:3000` 正常 | 安全组没放行端口，或 `HOST` 没设成 `0.0.0.0` |
| 上传 Excel 报 413 | Nginx 加 `client_max_body_size 10m;` |
| 刷新后数据丢失 | 检查进程工作目录，`DATA_FILE` 是否指向可写路径 |
| 中文文件名乱码 | 服务端已用 `filename*=UTF-8''`，用 Chrome/Edge 打开即可 |
| 端口被占用 | `PORT=8080 pm2 restart address-book --update-env` |
| 想改数据存放位置 | `DATA_FILE=/opt/data/contacts.json HOST=0.0.0.0 PORT=3000 pm2 restart address-book --update-env` |
