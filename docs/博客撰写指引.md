# CSDN 个人博客撰写指引

> **这份文档只讲一件事：怎么写并发布你的个人博客。**
> 代码保存、GitHub 上传、云部署都不在这里，那些已经做完了。你只需要照着本指引，把模板变成一篇可发布的博客。

## 先记住两件事

1. **要用模板**：`docs/博客模板.md`。设计思路、代码、问题与解决、分工依据、总结**都已经写好**，你主要是「填空 + 插图 + 改口吻」，不是从零写。
2. **每人一篇**：你和队友**各自发布一篇个人博客**，不能两人共发一篇。两篇内容可以共用素材，但口吻、PSP 时间、分工视角必须是各自的。

**视角说明（很重要）**：本指引按「**你 = 成员 A（后端与数据）**」来写。
- 模板里的「成员 A」就是你；
- 所有 `{{队友姓名（成员 B）}}` 之类的占位符，填**队友**的信息；
- 如果队友拿这份文档用，把 A / B 对调即可：他=成员 B，占位符填你的信息。

### 几个关键点的详细写法

**第 2 节 commit 数（别写错）**：模板里已列你的 3 次提交（`12ec43c`、`549d252`、`82ea01d`）。队友那边要写他**真实提交次数**。⚠️ 作业要求两人都要有提交——如果目前 3 次全是你的，让队友按之前的操作指引做一次真实改动并发 PR 合并后，再把数字改成实际的。**不要编。**

**第 7 节 PSP 合计怎么算**：
- 每行的「预估 / 实际」按你真实感觉填；
- `Planning / Development / Reporting` 三行是各自下面子项的**小计**，要等于子项之和；
- `合计 = Planning + Development + Reporting`。
- 填完自己加一遍，三个数对不上会被看出来。模板里的参考值是：成员 A 预估 540 / 实际 700，成员 B 预估 540 / 实际 725——**这是参考，按真实情况改**。
- 两篇博客的 PSP 不要填成完全一样的数字。

**口吻怎么改**：模板第 6 节成员 A 的 3 条问题、第 8 节成员 A 的总结，虽然是按后端视角写的，但那是「素材」。发布前用你自己的话顺一遍（换几个词、加一句你当时的真实感受即可），避免和队友博客读起来像同一个人写的。

4. 点发布，选原创，加标签（`#软件工程`、`#结对编程`、`#Node.js` 等）。
5. **发布后把你的博客链接提交到课程社区 `2601_FZU-MU_SE`**（原帖硬要求），并发给队友一份。

## 常见坑速查

| 现象 | 处理 |
| --- | --- |
| 链接点开是本地文件路径 | 从浏览器**地址栏**复制真实 URL，不要贴 `D:\...` |
| 主公网链接提示「链接不完整」 | `?sharecode=H3GSS33MLH` 那段被删了，补回去 |
| 博客里出现 `{{...}}` | 没填完，全局搜 `{{` 逐个检查（截图和队友姓名是最容易漏的） |
| PSP 合计对不上 | 检查小计是否等于子项之和、合计是否等于三个小计之和 |
| 两篇博客数字一模一样 | PSP、分工视角、口吻要各自调整，别整段照抄 |
| 说成「自建 ECS / 阿里云服务器」 | 如实写：主链接是云端 HTTP 服务，Vercel 是备用部署，别混为一谈 |
| 截图数字和别人不一致 | Vercel 冷启动会重置数据，如实说明是不同时间点截取 |
