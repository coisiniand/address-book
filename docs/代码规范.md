# EE308FZ 通讯录项目 · 代码规范

> 本文件可直接作为博客中「代码规范文档链接」指向的 GitHub 文件。
> 结对双方在开始编码前共同确认，并在 Code Review 时逐条检查。

## 1. 通用原则

1. 可读性优先于技巧；一个函数只做一件事，超过 80 行应拆分。
2. 所有面向用户的提示使用简体中文；代码标识符使用英文。
3. 不提交 `node_modules/`、日志文件、临时文件、包含隐私的真实通讯录数据。
4. 任何新增依赖都要在 PR 里说明理由，优先使用 Node 内置能力。
5. 不要写死端口、路径等环境相关值，统一放 `server/config.js` 并用环境变量覆盖。

## 2. 命名与格式

| 对象 | 规范 | 示例 |
| --- | --- | --- |
| 文件 / 目录 | 小写中划线或小写单词 | `contact-form`、`store.js` |
| 变量 / 函数 | 小驼峰，动词开头 | `buildWorkbook`、`handleAction` |
| 常量 | 全大写下划线 | `METHOD_TYPES`、`MAX_ROWS` |
| CSS 类名 | 小写中划线，BEM 风格 | `.contact-card`、`.card-footer` |
| 布尔值 | `is/has/should` 或形容词 | `bookmarked`、`paginate` |
| API 路径 | 复数资源名 + HTTP 动词表达动作 | `GET /api/contacts`、`PATCH /api/contacts/:id/bookmark` |

- 缩进 2 空格，UTF-8 编码，LF 换行，文件末尾留一个空行（由 `.editorconfig` 约束）。
- JS 语句一律以分号结尾；字符串统一用单引号，HTML 模板用反引号。
- 优先 `const`，需要重新赋值才用 `let`，禁止 `var`。
- 异步代码一律 `async/await` + `try/catch`，禁止回调嵌套；路由用 `wrap()` 统一捕获异常。
- 比较使用 `===` / `!==`。

## 3. 前后端职责边界

1. **后端是数据的唯一真相来源**：字段校验、类型白名单、时间戳、ID 生成、持久化都由 `server/` 负责，前端不做最终校验的替代。
2. **前端不直接拼 SQL/文件路径**，所有数据操作走 `public/js/api.js` 暴露的方法。
3. **API 统一响应格式** `{ code, message, data }`；`code === 0` 为成功，前端 `request()` 统一抛错，页面只负责 Toast 展示。
4. **联系方式类型表**以 `server/services/validate.js` 的 `METHOD_TYPES` 为准，前端 `public/js/utils.js` 保持同步；新增类型必须同时改两处并更新 Excel 列说明。
5. 导出与导入的列格式由 `server/services/excel.js` 一处定义，禁止在前端另造一套格式。
6. 渲染用户输入必须经 `esc()` 转义，防止 XSS；后端不信任任何请求体。

## 4. Git 工作流

### 分支

- `main`：随时可运行，只接受 PR 合并。
- `feat/xxx`：功能分支，如 `feat/backend-excel`、`feat/frontend-ui`、`feat/import-wizard`。
- `fix/xxx`：缺陷修复；`docs/xxx`：文档。

### 提交信息

```
<type>: <简短描述（不超过 50 字）>

可选正文：说明动机与影响范围
```

`type` 取值：`feat`（功能）、`fix`（修复）、`docs`（文档）、`style`（样式/格式）、`refactor`（重构）、`test`（测试）、`chore`（构建/依赖）。

示例：

```
feat: 实现 Excel 动态列导出与收藏状态往返
fix: 导入时同名合并策略重复写入联系方式
docs: 补充 PSP 表与云部署步骤
```

### 协作规则

1. 每次提交只包含一个逻辑变更，不混搭功能与格式化。
2. 提交前跑 `npm test`，确认全部用例通过。
3. PR 必须包含：改动说明、验证方式、截图（UI 改动时）；由队友 Review 后合并。
4. **两人都要有真实的代码提交**，仓库至少 3 次 commit；不代签、不伪造提交记录。
5. 完成后创建 Release（如 `v1.0.0`），并在博客中给出 commit 历史截图与各自提交数。

## 5. 测试要求

- 新增接口必须在 `scripts/smoke-test.js` 补充断言，运行 `npm test` 全绿。
- Excel 相关改动必须验证「模板 → 填写 → 导入 → 导出 → 再导入」往返一致。
- UI 改动至少在卡片视图、表格视图、窄屏（<860px）各检查一次。

## 6. Code Review 检查清单

- [ ] 命名清晰、无重复代码、无遗留 `console.log` 调试输出
- [ ] 所有用户输入在服务端做了校验，渲染时做了转义
- [ ] 错误有明确中文提示，不会把堆栈暴露给用户
- [ ] 新增字段同步更新 API 文档与 Excel 列说明
- [ ] 没有提交 `data/contacts.json` 中的真实隐私数据
- [ ] `npm test` 通过，页面手工验证通过
