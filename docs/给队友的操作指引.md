## 2. 第一步：把代码保存到自己电脑

### 方式 A：GitHub Desktop（推荐，不用敲命令）

1. 确认已安装 GitHub Desktop；没有就去 <https://desktop.github.com/> 下载安装（一路默认）。
2. 打开软件 → 顶部菜单 `File → Options → Accounts` → `Sign in to GitHub.com` → 浏览器里用**你自己的 GitHub 账号**授权登录。
3. 顶部菜单 `File → Clone repository…` → 切到 `URL` 页签 → 粘贴：

   ```
   https://github.com/coisiniand/address-book.git
   ```

4. 本地路径选 **D 盘**，例如 `D:\EE308FZ\address-book`（不要放 C 盘，也不要放在中文/空格特别多的路径）。
5. 点 `Clone`。完成后你就有完整代码了（`node_modules` 不在里面，这是正常的）。

### 方式 B：命令行（你电脑上已有 Git 才用）

打开 PowerShell，执行：

```powershell
cd D:\EE308FZ
git clone https://github.com/coisiniand/address-book.git
cd address-book
```

### 验证

打开 `D:\EE308FZ\address-book`，能看到 `server\`、`public\`、`docs\`、`data\`、`README.md` 就成功了。

> 如果你**只是写博客和截图**，其实到第 0 节打开网页就够了，clone 只是为了第 3 步提交代码。

## 4. 第三步：做一个真实改动并提交（你拿 commit 的关键一步）

不要凭空造提交，做一个**真实、有用、又不会破坏功能**的小改动即可。三选一：

- **改样式主色**：打开 `public/css/styles.css`，把主色调变量改一个色号（例如 `#2F5597` → `#2E7D5B`），保存。
- **补一句文档**：打开 `README.md`，在合适位置加一句你自己的说明，例如「本文档由结对成员共同维护」。
- **修一个错别字**：在 `docs/` 里找一处表述改准确。

### 提交（GitHub Desktop）

1. 回到 GitHub Desktop，左侧 `Changes` 会显示你改的文件，勾选它。
2. 左下角 **Summary** 填：`fix: polish UI theme and docs`（按你改的内容选一个：`style: adjust primary color` / `docs: clarify readme`）。
3. 点 `Commit to main`。
4. **一定要再点顶部 `Push origin`**（不点的话只是本地提交，GitHub 上看不到）。
5. 浏览器刷新仓库页，确认 commit 数从 3 变成 4，且作者是你。

### 提交（命令行备选）

```powershell
git add public/css/styles.css
git commit -m "style: adjust primary color"
git push origin main
```

### 截图留证

打开仓库首页 → 点 `4 commits` → **截图**，你的名字和队友的名字都要能看见。这张图放进博客第 2 节。

## 5. 第四步：发起 Pull Request（PR）

作业要求有 PR，按这个做最真实：

1. 在 GitHub Desktop 顶部菜单 `Branch → New branch`，起名 `feat/ui-polish`，基于 `main` 创建。
2. 在这个分支上再做**一个小改动**（例如再改一处样式或文档）→ Commit → `Push origin`（首次推送新分支要点 `Publish branch`）。
3. 浏览器打开 `https://github.com/coisiniand/address-book`，页面会出现黄色提示条 **`Compare & pull request`** → 点它。
4. 标题写 `feat: UI polish from teammate`，说明写「调整主题配色并补充文档」，点 `Create pull request`。
5. 让队友（项目主负责人）在网页上 Review → `Merge pull request`。
6. **截图 PR 页面**（能看到 `Merged` 状态）放进博客。

> 如果你不方便用分支，直接在 `main` 上改并 push 也行，但**至少要在网页上走一次 Pull request 页面**。不要伪造截图。

## 8. 常见问题

| 问题 | 处理 |
| --- | --- |
| `git` 不是内部命令 | 用 GitHub Desktop，不用命令行 |
| Clone 报错要登录 | Desktop 里先 `Options → Accounts` 登录 GitHub 账号 |
| Push 被拒 / 403 | 你不是协作者：让队友在仓库 `Settings → Collaborators → Add people` 邀请你，你邮件接受后再 push |
| 提交作者还是队友的名字 | 第 3 步没做，回去改 `Options → Git` 的 Name / Email，已提交的需让队友协助 rewrite（所以务必先改） |
| 网页打不开 Vercel 链接 | 等几秒冷启动；仍不行就用主公网地址（第 0 节第一个） |
| 页面数据变回 10 条 | Vercel 免费层 `/tmp` 冷启动重置，正常现象，演示时一次连续录完 |
| 博客链接点开是文件列表 | 说明填的是本地路径，要从浏览器**地址栏**复制 GitHub 文件 URL |
